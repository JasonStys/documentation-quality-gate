# Security policy

## Supported versions

The latest published major release receives security fixes. Pre-release branches and older majors are supported only when explicitly stated in their release notes.

## Reporting

Use GitHub private vulnerability reporting when available. Include the affected version, a minimal reproduction, impact, and suggested mitigation. Do not include credentials, private content, or unrelated personal data.

## Response targets

- Acknowledgment: within three business days.
- Initial assessment: within seven business days.
- Fix and disclosure timing: based on severity, exploitability, and downstream coordination.

## Safe-use boundaries

External network checks are disabled by default. Do not enable private-host access for untrusted pull requests. The project does not provide a code-execution sandbox and intentionally does not run documentation examples.
